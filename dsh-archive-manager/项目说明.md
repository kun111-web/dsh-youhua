# 归档管理实现说明

更新日期 2026-11-11。版本 2.4.1。使用流程及删除范围见 README.md。

## 实现

- `src/client/index.jsx` 在对话顶部及会话菜单注册删除入口。`src/client/App.jsx` 提供归档列表、子智能体列表和共用确认框。
- `src/manager.js` 管理归档记录和 5 分钟确认批次。按日志头的 `origin: subagent` 与 `parentSession` 发现后代，确认后整组复查，再按后代到父会话的顺序执行。`commit` 要求 `confirmed: true`，重复提交返回同一结果。
- `src/purge.js`：先复查文件清单，再取得原日志及副本的写租约，保存用量，持久化进行中标记，逐文件清理并复查。确认后增加或变化的文件不会自动加入删除。
- `src/copies.js` 检查主存储、登记的副本目录及对应缓存，支持只剩缓存的登记目录。依据日志头核对身份和父子关系，清理后检查文件不存在。删除标记存在时，阻止宿主为该会话重新写缓存。
- 归档列表和准备确认按请求共用一次日志目录扫描。提交时按指纹复用未改变的目录清单、日志头和缓存目录定位，在租约内仍发现新增副本并复核文件。登记目录不可用会暂停清理。无法读取的备份日志按路径提示。
- `src/index.js` 注册宿主接口、存储域和生命周期。从配置获取副本扫描目录。清理后触发已使用的全文索引同步。
- `src/session-release.js` 保存宿主在创建和恢复普通会话时返回的释放句柄。准备阶段只检查会话状态。用户确认后刷新日志并释放会话，驻留子智能体由宿主的 `drainChildren` 释放。释放后重新核对待清理文件。
- `../dsh-usage-stats/src/ledger.js`：用量持久化，按会话 ID 保存摘要，两插件共用同一个写队列。

## 状态和数据

删除标记在 `DSH_HOME/storages/archive_manager_local.json`。`deletedAt` 为开始删除时间，`purgePending` 表示清理未完成，`purgedAt` 为完成时间。子智能体记录的 `parentSession` 供清理中断后重试。发现已删除会话的文件重新出现时，归档管理会重新列出该项，等待用户确认。

`continuations` 在首个清理标记写入时登记根会话与首个处理项。父会话的文件尚未触碰时，也可从归档管理继续。旧格式续删记录按已持久化的清理标记判断是否允许取消归档。

用量保存在 `DSH_HOME/storages/usage_stats_local/`，与聊天日志独立。删除前校验主日志及副本的用量，再比较有效用量事件与已存摘要并保存最新记录。用量异常、分歧或副本无法完整读取时保留当前会话的日志。会话缓存通过宿主 storageDomain 删除，写回拦截防止迟到的缓存重新写入聊天内容。删除范围见 README.md。

历史已删除且没有用量记录的日志副本不能直接清理。迁移时应先使用可核对的原始记录保存摘要；文件名和标题不能用来估算 Token。

## 确认和失败处理

`prepare` 读取标题并捕获原日志、副本和缓存指纹。`commit` 在宿主队列中复查整组关系和文件，释放空闲会话后复核清单。如果有变化，则返回新确认凭据。清单通过核对后，逐个取得写租约、保存用量、清理副本和缓存，最后清理原日志。批次统一同步搜索索引和复查，完成后写入成功标记。

文件处理不是跨文件系统事务；若部分文件已删而后续失败，界面显示未完成，原有用量不丢失。刷新、重新确认后可继续，不能把清理中的记录恢复为普通会话。结果显示成功、跳过和未完成数量及原因。

## 验证边界

目标宿主固定为 DSH 0.2.2-rc.1。接口使用回环、同源、自定义请求头及 JSON 校验。使用了该版本的 persistence 租约、projection cache put 和 storageDomain 接口，宿主升级须重新验证。

npm 更新复用使用统计项目的更新实现，构建时打入归档管理包。待更新项在 Windows 版 DSH 完全退出后安装。若从 DSH 原生版本区手动更新，正在执行的批量删除和恢复会阻止安装。

自动测试覆盖管理状态、文件清理和拒绝条件。隔离宿主测试覆盖停止、单独清理子智能体、按父子关系清理和搜索索引更新。具体结果见 `qa/验证记录.md`。
