# DSH 归档管理 2.4.0

目标宿主为 DeepSeek Harness 0.2.2-rc.1。

从 npm 安装并启用 `dsh-archive-manager-local@2.4.0` 后，可在「插件 → 已安装插件」打开插件详情，选择「检查并更新」或开启「自动更新」。正在执行删除或恢复时会暂缓安装，待归档操作结束后可再次检查。

## 使用

- **直接删除**。会话空闲时，点击对话顶部的删除按钮，或在侧栏会话菜单选「删除会话…」。也可以先点「停止」，随即打开删除入口。插件会等待宿主收尾，确认后才保存并释放会话。仍有任务或排队输入时，页面会显示原因。
- **批量删除归档会话**。在「设置 → 归档管理」可删除当前筛选中已选的会话，或使用「删除搜索结果」处理当前结果。「继续清理」会重新列出上次未完成的会话及文件，待确认后继续。
- **单独删除子智能体**。在「设置 → 归档管理」点「子智能体」，选择会话后点「删除所选」。确认框会一并列出所选会话派出的各级子智能体。单独删子智能体时，父会话中已收到的消息及历史引用会保留。

核对确认框中的会话、文件和检查范围，点击「确认删除」。若保存和释放后待清理范围有变化，确认框会显示更新后的清单。再次确认后才删除。提交后可查看处理进度和索引同步状态。完成后会话从归档和搜索列表中移除，未完成的项目会显示标题和原因。

取消归档可将尚未清理的会话放回普通列表。用量校验在写入清理标记前失败时，仍可以取消归档。删除不可恢复，没有回收站或第二次删除入口。

## 删除内容与保留内容

- 清理本机当前 v4 会话日志、已登记扫描目录中同一会话的日志副本，以及对应的 `session_projcache` 会话缓存及可核验缓存备份。
- 先核对主日志和登记副本的用量。任一来源报告异常用量时暂停清理当前会话。可核对的最新用量保存在独立摘要中，删除和重启后仍可查看。摘要不含聊天正文。
- 保留项目文件、共享附件、用量存储及空目录。未登记的外部备份、云端副本不在此次核验范围内。
- 删除父会话时，子智能体后代会逐个清理，最后删除父会话。普通分支独立保存，存在普通分支时需先处理该分支。
- 同一批次按目录和文件指纹复用清单及日志头，逐条持租约复核。文件处理后同步一次已启用的本地全文搜索索引，复查主日志和副本均已清理后写入完成标记。
- 保存用量失败、文件或子智能体关系改变、被占用、路径异常或清理失败时，页面会显示跳过或未完成。部分清理中断后，可从归档管理继续处理。

确认框会列出每个会话的精确文件路径和检查的会话根目录。出现新的子智能体、副本或原文件变化，需要重新确认。清理以这些目录中的文件和应用搜索记录为范围，磁盘取证层面的擦除另计。

无法解析的备份日志会显示路径并保留。若损坏日志所在目录与目标会话或已识别的子智能体匹配，该组需先处理损坏文件才能继续。主存储或目录结构异常时会阻止清理。

## 副本扫描目录

本机 `cordis.patch.yml` 登记：

```yaml
backupScanRoots:
  - F:/dsh-youhua/dsh-usage-stats/.sandbox
  - F:/dsh-youhua/dsh-archive-manager/.sandbox
```

在这些目录中寻找会话根目录；不全盘搜索、不跟随链接、不进入依赖目录。`copy-tests` 和 `purge-tests` 为合成单元测试夹具，不属于历史聊天副本来源。将来若把会话备份到其他目录，需要把目录加入 `backupScanRoots` 后重新启动 DSH。

归档列表和删除确认框会显示已登记目录的状态。目录缺失、无法读取或路径异常时暂停清理。恢复目录后，刷新列表并重新核对。未配置额外备份根目录的环境只检查当前会话存储。

副本按日志内的会话 ID 验证，不按标题或模糊字符串删除。清理前会读取已登记日志副本的完整用量。旧前缀可由现有摘要覆盖，含有可核对新增用量的较新副本会先补齐摘要。日志分歧、无法完整读取副本，或主日志已不存在且没有摘要时，保留该会话的日志和副本。

## 安装与更新

本地开发时运行 `install.ps1` 安装 `dist/dsh-archive-manager-local-2.4.0.tgz`，再完全退出并重新打开 DSH。

```powershell
npm ci --ignore-scripts
npm test
npm run pack:plugin
```

后端构建引用相邻 `../dsh-usage-stats/src/ledger.js`，开发时保留两个源码目录。共享代码打入构建产物，安装后不依赖源码目录，也不要求统计插件已启用。

正式发版从工作区根目录运行 `node scripts/release.mjs`，统一测试、打包和校验两个插件。

## 验证

- `npm test`：单列表直接删除、旧记录迁移、确认批次、文件变化、身份核验、占用和失败保护。
- `node scripts/verify-live-archive-sandbox.mjs` 验证运行中拒绝、停止后直接删、单独删子智能体、父子清理顺序、文件与搜索索引复查，以及既有归档流程。
- `node ../dsh-usage-stats/scripts/verify-retention-sandbox.mjs`：真实宿主中的合成会话及副本/缓存清理，检查重启后用量。
- `npm run preview`：`http://127.0.0.1:19423` 的模拟数据界面，不操作真实会话。
- `scripts/clean-legacy-copies.mjs`：显式离线核对并清理已彻底删除会话的旧副本，先核对每个模型/日期的用量已保留。日常使用无需运行。

源码、构建产物和安装包分别在 `src/`、`lib/`、`dist/`；验证记录在 `qa/`。测试数据、真实数据副本与 QA 报告均不打包。来源与许可证见 NOTICE.md。
