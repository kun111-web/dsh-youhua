# DSH 使用统计插件项目说明

更新日期 2026-11-14。`dsh-usage-stats-local` 版本 1.3.5，支持 DSH 0.2.2-rc.1、rc.2 和 rc.3。

统计刷新和归档清理共用用量保存规则。当前摘要带有事件指纹时，比较日志与摘要的用量事件前缀。相互分歧时保留原摘要并提示。旧格式摘要仍可读取，当日志覆盖已记录的日期总量、模型用量和已知 Token 明细时补上指纹。

本插件在 **设置 → 使用统计** 展示当前本机 DSH 已记录的历史用量，包含已删除会话。界面直接参考 ZCode 官方使用统计页面，数据读取和宿主适配由本项目实现，不使用 dsh-scope。安装步骤见 [README](README.md)，工作区背景见 [总说明](../README.md)。

## 功能与统计含义

| 功能 | 含义 |
| --- | --- |
| 累计 Token | 已保存的会话摘要中，本分支新产生的完成消息用量汇总，包含已删除会话 |
| 峰值 Token | 单个自然日的最高 Token 总量 |
| 最长聊天时长 | 单会话本身事件首末活动的时间跨度，包含等待时间 |
| 连续使用天数 | 按宿主本地自然日计算；当前连续记录允许最后活跃日在昨天 |
| Token 活动 | 52 个自然周的每日、每周或累计展示 |
| Token 明细 | 最近 7 或 30 日的未缓存输入、输出、缓存读取、缓存写入，以及仍计入总量的未拆分用量 |
| 模型趋势与占比 | 最近 7 或 30 日，包含今天，按提供方和模型区分 |
| 导出统计 | 导出汇总 JSON，不包含聊天正文 |

页面支持深浅主题、窄面板布局、模型图例显隐和悬停提示。打开页面、手动刷新以及前台每 30 秒刷新数据。读取部分会话失败时会显示统计不完整，不把失败记录默认为完整的零用量。

### 每日 每周 累计的区别

- **每日**：每列是一周，每格是一天，颜色表示当天用量；未来日期不表示已发生活动。
- **每周**：每列是一周，用该列底部填充格子的高度和颜色表示当周总量。这些格子不是七份重复的每日用量。
- **累计**：每列表示从当前 52 周展示窗口开始、截至该周的累计用量，同样用列高和颜色表示。因此后续没有新增用量时，累计柱仍会保留已有高度。

高度和颜色根据当前模式的最大值归一化，所以不同模式的颜色不能直接当作相同 Token 数。顶部累计摘要覆盖可读取的全部历史；热力图累计只覆盖展示窗口，两者范围不同。

## 数据口径

生产插件使用宿主 `sessionPersistence` 只读读取会话。以完成的 `assistant/message.usage` 为准，优先使用 `totalTokens`；缺失时才累加输入、输出、缓存读、缓存写四个互斥桶，不额外叠加流式 usage，也不估算无 usage 的消息。

明细保存为每日可选字段 `tokenBreakdown`。旧台账可直接读取，仍有日志的旧摘要在首次扫描时补齐明细。只有总量或无法核对的部分保留为「未拆分」。当日志报告的总量恰好等于已记录分项之和时，省略的分项可计为零。

同一会话按事件 seq 去重，利用宿主提供的 `inheritedEventCount` 排除分叉继承前缀。相同模型名但不同提供方分别统计。日期按宿主本地时区划分，无活动日期补零。

统计不查询服务商账单、余额或套餐，不需要 API Key，也不调用模型。尚未写入日志的调用不计入。统计按会话 ID 持久化摘要，删除日志后保留摘要。归档管理 2.3.0 在彻底删除前核对主日志和登记副本，并保存最终总量及明细。其他程序直接删文件只保留最近成功保存的用量。升级前已删除且无摘要或可核对副本的历史无法自动补回。

## 源码与执行流程

| 文件 | 职责 |
| --- | --- |
| `src/index.js` | 宿主入口，注入 webServer 与 sessionPersistence，注册只读接口及卸载清理 |
| `src/collector.js` | 扫描会话、按 revision 更新持久化摘要、合并并发刷新、保留已删除会话 |
| `src/ledger.js` | 两插件共用的持久化存储、串行写队列、读句柄释放及删除前保存 |
| `src/aggregate.js` | 会话事件去重、继承前缀排除、日与模型聚合、摘要和连续天数 |
| `src/client/index.jsx` | 注册「使用统计」设置区、图标和样式 |
| `src/client/App.jsx` | 数据请求、刷新、导出、摘要和图表交互 |
| `src/client/model.js` | 日期窗口、模型序列、数字格式和热力图三种模式 |
| `src/client/style.css` | 页面布局、主题和响应式样式 |

启动、后台定时或设置页请求会列出当前会话，按 revision 重读有变化的日志，再返回用量汇总。台账写入、自然日变化或当前会话集合变化后才重新聚合。每次刷新仍核对会话并更新覆盖状态。日志读取与汇总在共享写队列之外完成，写入前复核 revision 和已保存摘要。记录保存在 DSH_HOME/storages/usage_stats_local/，包含会话 ID、revision、日期、模型、数值与用量事件指纹，不保存标题、项目路径或正文。首次创建时固定自然日时区。

接口为 `GET /api/dsh-usage-stats-local/snapshot`，要求 `x-dsh-usage-stats: 1`，并检查回环地址、Host、Origin 和 Fetch Metadata。当前不支持远程访问该插件接口。

技术组成：Node.js 24+、ES Modules、React 18、Recharts、Lucide、esbuild。构建时 React 由宿主提供，其余所需运行代码由构建脚本打包。

## 构建 安装与更新

在本插件目录执行：

```powershell
Set-Location 'F:\dsh-youhua\dsh-usage-stats'
npm ci --ignore-scripts
npm test
npm run build
```

`lib/index.js` 是宿主构建产物，`lib/client.js` 是前端加载产物。日常 desktop profile 使用安装包。源码修改后重新打包和安装，再完全退出并重启 DSH。

从工作区根目录运行 `node scripts/release.mjs`，生成 `dist/dsh-usage-stats-local-1.3.5.tgz` 并更新 SHA-256。当前包包含项目说明。

新版从 GitHub Releases 下载并手动安装。Release 只保留最新版，维护步骤见 [公开发布规则](https://github.com/kun111-web/dsh-youhua/blob/main/AGENTS.md#公开发布)。两个插件共用 `src/plugin-update-admission.js`，DSH 原生更新在取得 profile 写锁后核对活动任务。

## 工具脚本与隔离验证

| 脚本或命令 | 用途与边界 |
| --- | --- |
| `scripts/build.mjs` | 构建后端和前端产物 |
| `npm run preview` | 在 `127.0.0.1:19420` 预览；默认读取本机汇总快照，`?demo` 是模拟数据，另有 `?empty` 和 `?error` |
| `scripts/check-local-data.mjs` | 独立读取 v4 压缩日志并核对总量，输出 `qa/local-data.json`；只支持非 seeded 记录，不能替代宿主分叉读取验证 |
| `scripts/setup-sandbox.mjs` | 创建 `.sandbox/home`，复制本机 `.dsh/sessions` 以便隔离验证；不复制账户凭据，但会话正文仍是用户数据 |

运行隔离宿主的方法见 README。测试数据使用 `.sandbox/home`，端口 19419；日常数据使用 `C:\Users\ASUS\.dsh`。脚本应在本插件目录执行，`DSH_HOME` 只设在测试进程或当前测试 shell，结束后清除。不要直接分发整个 `.sandbox/` 或包含本机汇总信息的 `qa/`。

当前 24 项自动测试通过，覆盖旧摘要升级、用量冲突、仅剩副本时的核对和删除后保留。隔离宿主和页面检查见 [验证记录](qa/验证记录.md)及 qa/retention-integration.json。

## 常见问题与维护位置

| 现象 | 检查方法 |
| --- | --- |
| 设置没有使用统计入口 | 检查 profile 是否加载插件、`lib/` 是否存在，完全退出并重启 DSH |
| 修改源码没有生效 | 先执行 `npm run build`；若使用 tgz 安装，还需重新打包并安装 |
| 与账单不同 | 按已保存的历史用量口径核对，不把页面总量当作服务商账单 |
| 删除后统计仍有用量 | 预期行为：摘要独立保留，刷新和重启都不会删除 |
| 每周和累计出现整列格子 | 这是周总量或窗口累计的柱状表达，悬停查看对应周与数值 |
| 统计不完整 | 排查不可读日志；先保留失败提示，不能直接把失败项忽略为零 |
| 首次刷新较慢 | 首次需扫描全量历史；后续按会话 revision 复用缓存 |

更改统计规则时优先修改 `aggregate.js` 和相关测试；更改热力图表达时检查 `client/model.js`；宿主读取兼容问题检查 `collector.js` 与 `index.js`。
